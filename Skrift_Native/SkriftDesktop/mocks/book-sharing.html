The format

The Odyssey.skriftbook          UTI com.skrift.book → public.zip-archive, public.data
├── manifest.json                schema · the Audiobook record · file list
├── audio/Odyssey-01.m4a …       ordered, original filenames
├── cover.jpg
├── text/wilson-odyssey.epub     if one is attached
└── derived/transcript_f0.json · derived/alignment_f0.json

never in a bundle: bookmarks, position, playback rate, notes, captures

A ZIP. ZIPFoundation is already dep #2 (pinned 0.9.20, app target) and streams entry-by-entry, so 797 MB needs no new dependency and no memory ceiling. Audio entries stored .none (already compressed), JSON deflated.

The transcript + alignment ride along as plumbing — invisible in the UI, ~13 MB against 782 MB, and they save the recipient hours of ANE time. Strip them and the receiving phone has to re-transcribe the whole book.

What the engine has to get right

  • Re-stamp the transcript on arrival. BookTranscriptStore.signature is "<size>:<mtime>" of the local audio; mtime changes when the receiver writes the file, so an un-restamped sidecar reads as stale and the book silently looks un-transcribed. AudiobookCloudSync.restampTranscripts already does this for the CloudKit path — hoist it to one shared re-stamper, don't grow a second copy.
  • Keep the book id. Import keyed on the manifest's bookID: already present → screen 4b, nothing happens. That's the only reason the id matters now — re-importing the same file twice can't duplicate a book.
  • No duration matching, no merging. Both fell out when audio became unconditional: a bundle's transcript always arrives with the audio it was measured against, so it can never be attached to a different rip.
  • Local-only fields. epubChapters / detectedChapters are derived from local sidecars. Import writes the files and re-derives; it doesn't trust the manifest's copy.
  • Tests can't link ZIPFoundation ("app target ONLY — extensions and test bundles never touch archives"), so the testable surface is the manifest codec + the already-have-it check + the re-stamp. The zip I/O is a thin shell verified on device.

Wiring

  • Out: a ShareLink over the packaged temp file. AirDrop, Files and Messages come free.
  • In: CFBundleDocumentTypes entry, LSHandlerRank: Owner → .onOpenURL → a book-bundle branch in AppURLHandler. Plus the book UTI added to the Books + fileImporter so Files works too. No new app extension.
  • Per-config UTI: com.skrift.book (Release) / com.skrift.book.dev (Debug), Dev accepting both. Dev and Prod run side by side; if both export the same type, document routing is undefined and a test bundle can open in the prod app.
  • iPad rides along. The Mac has no book library — a .skriftbook there is storage, not an import.
